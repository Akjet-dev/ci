# Чарт `akjet-app`

Один общий чарт для сервисов: один образ, несколько компонентов (Deployment) с разными командами,
опционально Service, HTTPRoute и Job миграций. Чарт ничего не знает о базах, объектных хранилищах,
очередях и платёжных провайдерах: для него это переменные окружения. Новая переменная или
интеграция — это правка values сервиса, а не чарта.

## Что чарт создаёт и чего не создаёт

| Создаёт | Никогда не создаёт |
|---|---|
| Deployment на каждый компонент | Secret с данными |
| Service (ClusterIP) для компонентов с `service.enabled` | Namespace, NetworkPolicy, ResourceQuota, LimitRange |
| ConfigMap `<release>-config` из `config` | Role, RoleBinding, любые кластерные объекты |
| ServiceAccount `<release>` без токена API | Gateway, сертификаты |
| HTTPRoute — только при `httpRoute.enabled: true` | PersistentVolumeClaim, StatefulSet |
| Job миграций — только по запросу workflow деплоя | |

Неймспейс в манифестах не указывается: его задаёт только workflow деплоя.

## Структура values

| Ключ | Назначение |
|---|---|
| `image.repository`, `image.digest` | образ. Digest `sha256:<64 hex>` обязателен, теги отвергаются схемой. Digest подставляет workflow |
| `imagePullSecrets` | имена существующих pull-секретов в неймспейсе |
| `podSecurity.runAsUser`, `runAsGroup`, `fsGroup` | числовой пользователь, если образ его не задаёт |
| `readOnlyRootFilesystem` | по умолчанию `true`; каталоги для записи — в `writablePaths` |
| `config` | несекретные переменные для всех компонентов (ConfigMap). Значения — строки |
| `requiredSecrets` | объявление Secret'ов, которые должны существовать: `имя: [ключи]`. Объект называется `<release>-<имя>` |
| `envFromSecrets` | объявленные Secret'ы, подключаемые целиком |
| `secretEnv` | отдельный ключ под своим именем переменной: `ПЕРЕМЕННАЯ: {secret, key}` |
| `secretFiles` | ключ Secret'а как файл только для чтения: `{secret, key, mountPath}` |
| `components.<имя>` | компонент, см. ниже |
| `httpRoute` | маршруты, по умолчанию выключены |
| `migration` | Job миграций, по умолчанию выключен |
| `rolloutRevision` | смена значения перезапускает pod'ы без смены образа |

Компонент:

| Ключ | Назначение |
|---|---|
| `replicas` | по умолчанию 1 |
| `command`, `args` | по умолчанию — из образа |
| `ports` | `имя: порт`, порт не ниже 1024 |
| `service.enabled` | Service `<release>-<компонент>` с теми же портами |
| `strategy` | `RollingUpdate` (без простоя, по умолчанию) или `Recreate` (не больше одной реплики) |
| `terminationGracePeriodSeconds` | время на завершение, по умолчанию 30 |
| `probes.startup`, `readiness`, `liveness` | `{path, port}` либо `{exec: [...]}`, плюс периоды и пороги |
| `resources` | обязательны: запросы CPU и памяти, лимит памяти |
| `writablePaths` | каталоги, монтируемые как `emptyDir` |
| `config`, `envFromSecrets`, `secretEnv` | то же, что на уровне релиза, но только для этого компонента |

Полная схема с ограничениями — `charts/akjet-app/values.schema.json`; примеры — `charts/akjet-app/ci/`.

## Секреты

Чарт только ссылается на существующие Secret'ы и никогда не видит их значений.

- Каждый Secret, на который есть ссылка, должен быть объявлен в `requiredSecrets`, иначе рендер
  завершается ошибкой. Объявление — единый перечень того, что сервису нужно от платформы.
- В `config` запрещены имена, похожие на учётные данные (`*PASSWORD*`, `*SECRET*`, `*TOKEN*`,
  `*ACCESS_KEY*`, `*_KEY`): такие значения должны лежать в Secret.
- В данные релиза Helm попадают только имена Secret'ов и ключей.
- После изменения Secret pod'ы сами не перезапускаются: нужен деплой с `restart: true`.

Порядок источников в контейнере: ConfigMap релиза, затем Secret'ы релиза, затем Secret'ы компонента
(более поздний перекрывает более ранний); явные переменные (`components.<имя>.config`, `secretEnv`)
перекрывают всё.

## HTTPRoute

Выключен по умолчанию. **Через `deploy-k8s.yml` не деплоится**: маршруты сервисов принадлежат
платформе (компонент gateway-route в k8s-infra), и проверка манифестов отклоняет релиз приложения с
HTTPRoute. Шаблон остаётся в чарте для использования вне общего workflow.
При `httpRoute.enabled: true` обязательны `parentRef.name`, `parentRef.namespace` и явные `hostnames`
у каждого маршрута; шаблоны с `*` отвергаются. Компонент маршрута должен иметь Service.

## Миграции

Job миграций не входит в релиз Helm и не является hook'ом. Workflow деплоя рендерит его отдельно
(`migration.render=true`, уникальный `migration.runId`) и запускает до `helm upgrade`. Поэтому Job не
зависит от объектов релиза: несекретная конфигурация встроена в него переменными, Secret'ы
подключаются по имени, ServiceAccount — `default` без токена.

`migration.config` перекрывает `config` релиза — так задаётся отдельная роль базы для миграций.
Автоматического отката схемы нет: миграции должны быть обратно совместимыми.

## Безопасность по умолчанию

Манифесты соответствуют профилю Pod Security `restricted`: запуск не от root, `seccompProfile:
RuntimeDefault`, запрет повышения привилегий, сброс всех capabilities, корневая файловая система только
для чтения, токен ServiceAccount не монтируется, ссылки на сервисы неймспейса в окружение не
добавляются. Отключить это через values нельзя, кроме `readOnlyRootFilesystem`.

## Чего в чарте нет

HPA, PodDisruptionBudget, CronJob, ServiceMonitor, init-контейнеры, тома с данными. Возможность
добавляется, когда она нужна минимум двум сервисам; иначе сервис может использовать собственный чарт
(вход `chart: ./путь` в workflow деплоя).

## Версии

Версия чарта — semver в `Chart.yaml`. Несовместимое изменение схемы values — новая major-версия.
Сервисы закрепляют точную версию во входе `chart-version`.
