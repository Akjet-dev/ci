# Совместимость общих workflow с сервисами

Все сервисы обязаны работать на одном и том же коммите `Akjet-dev/ci`. Этот документ описывает контракт,
автоматическую проверку и порядок выпуска.

## Потребители

Список — `tests/consumers.yaml`: `backend`, `lk-frontend`, `executor-frontend`, `landing`, `bcc-kommo-api`.
Новый сервис добавляется туда вместе со снимком своих вызовов (`tests/consumers/<имя>.json`).

## Контракт

| | `build-image.yml` | `deploy-k8s.yml` |
|---|---|---|
| Обязательные входы | нет | `environment`, `chart-version` |
| Необязательные входы | `image`, `context`, `dockerfile`, `target`, `build-args`, `platform`, `cache`, `push`, `scan`, `scan-fail-on` | `validate-only`, `image-digest`, `release`, `values-dir`, `chart`, `run-migrations`, `restart`, `timeout`, `pod-logs-on-failure`, `env-bundle-secret` |
| Секреты (все необязательные) | `build-secrets` | `app-secrets`, `env-bundle` |
| Выходы | `image`, `digest`, `published` | нет |
| Права токена у вызывающего job'а | `contents: read`, `packages: write` | `contents: read`, `packages: read` |

Всё, что зависит от типа приложения, включается только явной передачей:

| Возможность | Включается | Если не передано |
|---|---|---|
| Набор окружения | секрет `env-bundle` | шаг сообщает «No env-bundle was passed» и ничего не делает |
| Сквозной режим набора | вход `env-bundle-secret` вместе с `env-bundle` | набор проверяется по объявлениям сервиса, как раньше |
| Явные секреты приложения | секрет `app-secrets` | Kubernetes Secret'ы не трогаются, `kubectl` не вызывается |
| Миграции | вход `run-migrations: true` | Job не рендерится и не создаётся |
| Переопределения переменными | файл `deploy/overrides.yaml` | действуют values-файлы |
| Секреты сборки | секрет `build-secrets` | сборка без секретов BuildKit |

Отсутствие необязательного — не ошибка. Включённая возможность проверяется строго: неизвестный вход или
секрет, лишний ключ набора, недостающее обязательное значение останавливают запуск.

## Проверка

```bash
tests/run.sh                                         # всё, включая совместимость
tests/check_consumers.py --workspace .. --against-pinned    # только совместимость, по реальным файлам сервисов
```

`tests/check_consumers.py` всегда проверяет **кандидата** — файлы workflow в рабочем дереве `ci`, а не
опубликованную ревизию. Источник вызовов сервисов:

| Где запущено | Что проверяется |
|---|---|
| Рабочая станция, сервисы лежат рядом с `ci` | реальные workflow, values и Dockerfile пяти сервисов; снимки сверяются с ними |
| CI, задан секрет `CONSUMERS_READ_TOKEN` (только чтение пяти репозиториев) | то же: ветки из `tests/consumers.yaml` скачиваются `tests/fetch-consumers.sh` |
| CI без токена | снимки `tests/consumers/*.json`: входы, секреты, выходы, права, неймспейсы |

Снимок — не копия workflow, а перечень вызовов: какой файл, какие входы, какие секреты, какие права. Он
обновляется командой `tests/check_consumers.py --workspace .. --write-snapshots` при изменении вызовов сервиса.
Смена SHA снимок устаревшим не делает.

Правила: K1 ссылка на существующий workflow и полный SHA; K2 входы; K3 секреты (в том числе «Invalid secret,
… is not defined in the referenced workflow»); K4 выходы; K5 права токена; K6 секреты рантайма только при
деплое в `dev`, не вместе и не из чужого окружения; K7 локальные reusable workflow; K8 версия чарта; K9
неймспейс совпадает с платформой; K10 одна ревизия у всех. По файлам сервиса дополнительно: H1 Helm
(`lint`, `template`, `kubeconform`, политика безопасности), D1 контракт сборки Docker, O1 необязательные шаги
без входов ничего не делают.

Это статическая проверка. Она не заменяет запуск в GitHub Actions: принял ли GitHub workflow, видно только
по реальному запуску на ветке без деплоя.

## Какие изменения совместимы

| Совместимо | Несовместимо |
|---|---|
| новый необязательный вход или секрет | удаление или переименование входа, секрета, выхода |
| новый выход | вход становится обязательным; меняется его тип |
| новый шаг, который без своего входа ничего не делает | изменение умолчания, которое меняет поведение существующего вызова |
| более строгая проверка новой возможности | новая проверка, которую не проходит существующий сервис |
| новая версия чарта рядом со старой | изменение правила неймспейса, имени релиза, ветки деплоя |
| | повышение требуемых прав токена или RBAC раннера |

## Несовместимое изменение

1. Добавить новое рядом со старым (новый вход, новый файл workflow), старое оставить работающим.
2. Выпустить `ci`, перевести все сервисы на новую ревизию и новый интерфейс.
3. Убедиться, что `tests/check_consumers.py --workspace ..` не находит ни одного вызова старого интерфейса.
4. Только после этого удалить старое отдельным выпуском `ci`.

Удаление в один шаг запрещено: проверка совместимости в `tests/run.sh` его не пропустит.

## Порядок выпуска

1. Изменения в `ci`.
2. `tests/run.sh` — все проверки, включая пять сервисов.
3. PR в `main`, слияние.
4. `git fetch origin && git rev-parse origin/main` — SHA выпуска. Убедиться, что Chart CI на `main` зелёный.
5. `scripts/update-ci-sha.sh <SHA>` — пробный прогон: проверяет ревизию и показывает diff.
6. `scripts/update-ci-sha.sh <SHA> --apply` — правит рабочие копии пяти сервисов; ничего не коммитит.
7. В каждом сервисе: коммит в ветку `dev-k8s/<задача>` (не `release`), push — проверка и сборка без деплоя.
8. Просмотр запусков; слияние в `dev-k8s/release` — отдельным решением по каждому сервису.

`scripts/update-ci-sha.sh` меняет только строки `uses: Akjet-dev/ci/.github/workflows/(deploy-k8s|build-image).yml@<sha>`
в `k8s-*.yml`. Ссылки на другие actions, включая `Akjet-dev/ci/netbird@…` действующего деплоя, не трогаются.
Ревизия должна быть полным SHA коммита из `origin/main`; ветки, теги и заглушка из нулей отклоняются.
